# movie-review-ai

**Version:** 1.0
**Status:** Proposed
**Target Platform:** Apple Silicon Mac Studio M5 Max, 128 GB unified memory
**Primary Goal:** Convert a full-length movie into an approximately 20-minute, YouTube-style review video using local AI with no mandatory cloud AI dependency.

---

# 1. Product Vision

`movie-review-ai` is an offline-first AI production pipeline that transforms:

```text
movie.mp4
```

into:

```text
review/
├── movie-analysis.json
├── review-outline.json
├── review-script.md
├── review-script.json
├── narration.wav
├── subtitles.srt
├── review.mp4
├── thumbnail.png
└── manifest.json
```

The system must understand the movie before writing the review.

It MUST NOT treat the task as:

```text
movie → transcript → LLM summary
```

Instead:

```text
movie
  ↓
media extraction
  ↓
scene/shot timeline
  ↓
speech recognition
  ↓
visual understanding
  ↓
character identification
  ↓
event extraction
  ↓
story graph
  ↓
evidence-backed movie knowledge base
  ↓
review planning
  ↓
script generation
  ↓
fact/continuity verification
  ↓
visual planning
  ↓
TTS
  ↓
automatic editing
  ↓
quality control
  ↓
final review video
```

# 3. Output

The default target is:

```text
20 minutes
± 30 seconds
```

Target narration:

```text
2,800–3,200 words
```

Default:

```text
150 WPM
```

The exact target SHALL be calculated dynamically:

```text
target_words =
    target_duration_seconds
    × target_wpm
    / 60
```

Example:

```text
1200 × 150 / 60
= 3000 words
```

# 4. Design Principles

## P1 — Evidence First

Every important factual statement generated by AI SHOULD be traceable to:

* dialogue
* scene
* frame
* event
* character
* timestamp

No important plot claim should exist without evidence.

---

## P2 — Deterministic Before Generative

Use deterministic tools wherever possible:

```text
FFmpeg
PySceneDetect
SQLite
hashing
timestamp calculations
duration calculations
JSON schema validation
```

Use LLMs only where interpretation is required.

---

## P3 — Small Context Windows

Do not put the entire movie into one LLM context.

Use hierarchical processing:

```text
shot
 ↓
scene
 ↓
sequence
 ↓
story event
 ↓
movie-level story
```

---

## P4 — Restartable Pipeline

Every stage must be independently restartable.

If TTS fails:

```text
DO NOT re-analyze movie
```

If script changes:

```text
DO NOT rerun ASR
DO NOT rerun scene detection
```

---

## P5 — Model Agnostic

AI models SHALL be configured rather than hard-coded.

Example:

```yaml
models:
  vision:
    provider: mlx-vlm
    model: Qwen3-VL

  reasoning:
    provider: mlx-lm
    model: Qwen3.5-27B

  tts:
    provider: mlx-audio
    model: Qwen3-TTS-1.7B
```

# 10. Stage 2 — Media Extraction

Generate:

```text
audio/dialogue.wav
audio/music.wav
video/proxy.mp4
frames/
```

Recommended analysis proxy:

```text
1280×720
```

Do not repeatedly decode the original 4K/8K source for AI analysis.

---

# 11. Stage 3 — Scene Detection

Primary:

```text
PySceneDetect
```

Generate:

```json
{
  "scene_id": "scene_000123",
  "start": 1532.21,
  "end": 1549.82,
  "duration": 17.61
}
```

Additional metadata:

```text
shot_count
cut_density
motion_score
brightness
audio_energy
```

---

# 12. Stage 4 — Adaptive Frame Sampling

Sampling MUST NOT be uniform only.

Default:

```text
scene < 10 sec:
    2–4 frames

10–60 sec:
    4–8 frames

60+ sec:
    8–16 frames
```

Increase sampling when:

```text
high motion
high cut density
new character
new location
dialogue transition
detected action
visual anomaly
important story event
```

Reduce sampling when:

```text
static conversation
repeated frames
dark/static shot
low visual information
```

---

# 13. Stage 5 — ASR

Default model:

```text
Whisper large-v3-turbo
```

Whisper large-v3-turbo is the pruned faster variant of large-v3, with four decoder layers instead of 32 and a smaller quality tradeoff.

Current official checkpoint is multilingual and supports 99 languages.

Output:

```json
{
  "segment_id": "seg_00042",
  "start": 123.44,
  "end": 127.12,
  "text": "Where were you last night?",
  "language": "en",
  "confidence": 0.94
}
```

The system MUST preserve word/segment timestamps.

---

# 14. Stage 6 — Speaker Diarization

Output:

```text
SPEAKER_00
SPEAKER_01
SPEAKER_02
```

Do not immediately rename speakers.

Character identity is resolved later.

---

# 15. Stage 7 — Scene Visual Analysis

Primary model:

```text
Qwen3-VL
```

Qwen3-VL is specifically designed around enhanced visual perception, spatial reasoning and video dynamics understanding.

Each scene receives:

```text
keyframes
scene metadata
relevant dialogue
previous scene summary
```

The model must produce:

```json
{
  "scene_id": "scene_000123",
  "location": "...",
  "characters": [],
  "actions": [],
  "objects": [],
  "emotions": [],
  "visual_events": [],
  "importance": 0.82
}
```

# 30. Script Rules

The generated script MUST:

1. Tell the story clearly.
2. Maintain chronological coherence unless intentionally using a non-linear structure.
3. Avoid unsupported facts.
4. Avoid inventing dialogue.
5. Distinguish movie facts from interpretation.
6. Avoid excessive scene-by-scene narration.
7. Maintain YouTube pacing.
8. Use transitions.
9. Build suspense.
10. Pay off the hook.
11. Respect target duration.
12. Include the ending when spoilers are enabled.

---

# 33. Fact Checker Agent

Input:

```text
review-script.json

```

Output:

```json
{
  "claims": [
    {
      "claim_id": "claim_001",

    }

```

Allowed statuses:

```text

CONTRADICTED
INSUFFICIENT_EVIDENCE
```

Rules:

```text

INSUFFICIENT_EVIDENCE
    → remove or convert to clearly marked interpretation

PARTIALLY_SUPPORTED
    → writer must qualify statement
```

# 40. Narration Chunking

Never synthesize the entire 3,000-word script in one request.

Chunk by:

```text
paragraph
```

or approximately:

```text
20–60 seconds
```

Each chunk:

```text
tts_001.wav
tts_002.wav
tts_003.wav
```

Then concatenate.

This allows:

```text
retry
emotion changes
speed changes
paragraph editing
```

without regenerating the entire narration.

# 57. Memory Manager

The system SHALL treat unified memory as a shared resource.

Before loading a model:

```text

estimate_kv_memory()
estimate_frame_memory()
```

If memory budget is exceeded:

```text
unload current model
clear MLX cache
load next model
```

Never assume:

```text

```

The operating system, filesystem cache, FFmpeg, Python and other processes also consume memory.

# 66. Context Overflow Handling

Never blindly increase context.

If:

```text
input > model_context
```

then:

```text
retrieve smaller evidence set
```

or:

```text
hierarchical summarize
```

or:

```text
split task
```

---

# 67. OOM Handling

If MLX reports memory pressure/OOM:

```text
1. stop generation
2. unload model
3. clear cache
4. reduce batch
5. reduce frame count
6. reduce context
7. retry
```

Do not automatically reduce output quality first.
